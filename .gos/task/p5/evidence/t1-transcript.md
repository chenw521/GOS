# T1 dogfood transcript — post-P5 card contract in a real dialogue

Provenance: excerpt of the session dialogue on this task's branch, recorded
at .gos/task/p5/evidence/t1-transcript.md. The exchange (rendered in
English) happened between BUILD waves of this task: the user asked to
re-examine which gitignored files should become tracked repo assets. The
dialogue follows the P5 contract end to end — dig before the card, a
5-column card whose Activates cells name concrete consumers, a conditional
recommendation, a standing deepen tail line, and two deepen rounds each
opened by a `new facts:` line.

## Round 1 — card after the disposition dig

The dig surveyed every ignored store first (sizes, CJK density, personal
traces, consumers in bin/lib), then the card:

| Option | Premise | Pros | Cons | Activates |
|:--|:--|:--|:--|:--|
| knowledge minimum set (trio + lessons + concerns) | cross-machine, history-preserving value is highest; English guard arms itself once tracked | 32+37 CJK lines need rewriting first; one `gos track` transaction per file | knowledge files travel with every clone and are write-constrained to English | `gos track` flips x5 + CJK rewrite mini-task |
| minimum set + Lv4 generated views | the five views are already all-English, zero rewrite cost | PR reviewers see roadmap and decision index | generated views in git add a drift surface (no regen guard yet, README-style guard needed) | the above + a generated-view regen guard task |
| everything incl. archive/ 2.9M + logs/ | most complete history | none | every commit polluted by ledger appends; re-triggers the CJK+privacy audit rejection | none (expected rejection) |
| keep as-is | the boundary was audited and ruled before | zero cost | cross-machine knowledge keeps leaking; opposite of the user's ask | none |

why-not: everything — 2.9M archives plus append-heavy ledgers recreate the
rejected shape; keep-as-is — contradicts the re-examination request.
recommendation: knowledge minimum set — conditional: upgrade to the
Lv4-view set only if PR-review visibility outweighs adding a regen guard.
deepen: any option — ask for another dig round.

## Round 2 — deepen, opened by the increment

new facts:
- the guide trio (structure/conventions/concerns.md) has zero CJK, zero
  machine paths, zero usernames — zero rewrite cost, one-command flip
- lessons.json holds 62 entries with zero paths/emails/URLs — translation
  only, no scrubbing
- root concerns.md carries exactly one personal trace (a home path plus an
  internal IP inside a privacy checklist line) — surgical one-line scrub
- English is enforced mechanically (cjk-lint + track pre-scan + the
  tracked-store write guard), not by discipline

Card re-presented with the user's criterion (outsider reusability) as the
new premise; Lv4 views re-classified as personal process output and
dropped to machine-local by the user's ruling.

## Round 3 — second deepen

new facts:
- the 37 Chinese lessons are high-value durable discipline (three marked
  permanent), a few carry stale monolith-era line references, so the
  rewrite pass must triage per entry rather than translate blindly
- the trio is a live asset but structure.md still says "state schema v4"
  and needs a one-line refresh once this task's v5 lands

Empty increment would have closed the port; instead the execution contract
was refined (translate + triage + scrub + flip + verify) and the ruling
was recorded as a concern entry for a post-SHIP mini-task.
